## 3. 四周课程（从 Day 01 的知识域开始，不机械一日一文件）

### 第 1 周：基础面试题复盘／重新建立可信基线

| 课次 | 主要题目 | GitHub 源 |
|---|---|---|
| 1 | 自己紹介（60–90秒）、当前工作、強み、赴日理由的首次盲测 | Day 01～05 |
| 2 | 同四题中 B/C 项复测；加入弱点、工作时间线 | Day 05、09～12 |
| 3 | 失敗した経験 + 一番大変だったこと；区分经历、原因、反思 | Day 10～15 |
| 4 | チームで大切にしていること、团队协作；补早期弱项 | Day 15～21 |
| 5 | 四类主题混合抽问、阶段诊断更新；不固定顺序 | Week 1 全部 |

### 第 2 周：行为面试与独立叙事

复习 Day 17～30 中的“问题 → 处理 → 结果”、失败经历、团队协作、当前工作、赴日理由。把会背两句提升为临时追问 2～3 轮。每日保留 Week 1 到期题，按实际分数调整。

### 第 3 周：MuleSoft / API / 技术面试

重点 Day 34～39：API 移行、WSDL、SOAP、名前空間、修正、結合テスト、影響確認、結果・効果、团队共享。加入适量 Java / SQL 问法，但是技术内容以真实做过的项目为准，不编造业绩。混入基础面试题以防遗忘。

### 第 4 周：综合模拟与缺口修补

不提前展示问题的 15～20 分钟日本 IT 面试模拟，覆盖自己紹介、履历、项目、团队、技术和赴日理由。每次复盘按听力理解/内容/自主程度/语法/流畅度评估，下一堂课以最低分维度决定训练重点。

**周内进度可浮动**：不是规定 5 天强行完成。若新测发现前置能力仍弱，可适当延长，但不让全程只围绕一两个句子打转。

## 4. 每堂课默认结构（目标 30～40 分钟，可按用户状态调整）

1. **5 分钟｜听力热身**：3～4 个日语问句，先判断问意，再自由回答；需要重说就重说，区分“没听清”与“没理解”。
2. **10 分钟｜到期旧题**：从错题表自动挑选上次评级 B/C、以及 1/3/7/14 天到期的 A 题。
3. **10 分钟｜本阶段主线**：围绕本课 2～3 个问题进行独立回答及少量追问；不提前显示答案。
4. **7～10 分钟｜随机面试**：换题，不提供答案，练连续输出和应变。
5. **3～5 分钟｜教师复盘**：更新得分、错因、复测日和下一堂课的重点。

**用户提出停课即停课**，不强行为凑满 30 分钟继续提问。不要每过两题便擅自宣布结束。

## 5. 单题五维评分标准（首次独立输出，0～20 分）

每项 0～4 分：

| 维度 | 4 分定义 | 2 分定义 | 0 分定义 |
|---|---|---|---|
| 问题理解 | 不翻译、不提示，理解并准确切题 | 重说或少量释义后理解 | 仍无法理解 |
| 内容切题与完整 | 要点充分、没有偏题 | 核心意思有但缺要点 | 无内容/偏题 |
| 独立输出 | 不看文本、不听模板，能自主答 | 需要关键词提示 | 直接跟读/无法说 |
| 语法与措辞 | 面试自然、误差不妨碍理解 | 小范围语法问题 | 错误严重妨碍理解 |
| 连接与流畅度 | 有条理连续表达 | 停顿但能继续 | 完全无法组织 |

- **A**：17～20 且每项至少 2；**B**：13～16；**C**：0～12；若 17+ 但有一项低于 2，则最多 B（需修短板）。
- 首次回答才打正式分；提示后修改另记“辅助练习表现”，不覆盖首次分数。
- 不给语音转写无法支撑的“精确发音”分数；声音故障/没听到单独记录。
- 题目掌握的最低标准：跨至少两个不同日期**无提示 A**，中间至少间隔 3 天；达到后进入保持复习，不永久删除。

## 6. 间隔复习与错题闭环

| 首次评级 | 后续复测 |
|---|---|
| C | 次日优先；当天只纠关键原因，不反复磨一个词 |
| B | 次日或下一次上课优先；再次自主达标后安排 +3/+7 天 |
| A | +3 天、+7 天、+14 天抽查；保持长期记忆 |

记错题时包含：原问题、首次回答的关键问题、正确但简短的固定版、是否为“听力/词汇/语法/语序/时态/流畅/题意不符”、下次复测日、首次独立得分、提示后表现。只修主要 1～2 个错误。

## 7. 教师主动责任

- 每次用户提出“开始练习”“今天继续”“Day 40”或“复习”时，先看 GitHub 上本计划和最新进度，**由教师自动确定当天题目**。
- 不必用户指定“今天学什么/复习什么”；上课开始时简单告知今日目标，然后一题一题地问。
- 每次结束后给出客观成绩，并在获授权或沿用既有写入流程时更新 GitHub 进度。
- 不因为跟读成功就判定掌握；不因为语音识别混淆就过度纠结发音。
- 若用户说“不想继续”“差不多得了”，立即结束提问、做简短总结。
- 本计划不能在聊天外自动完成提醒/授课/监控；需要用户进入对话开始课堂，或另行建立明确的定时提醒。
