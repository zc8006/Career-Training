适合个人起步  首周完成样片  首月预算上限200元

价格核对日期 2026年10月16日  金额为人民币

建议从旁白型二维动态漫开始：先做好剧本、人物和分镜，再用配音、镜头推拉和少量AI视频组成完整短片。首周做出一条45～60秒样片，首月完成6条，用成片时间、实际花费和观众反馈判断是否继续投入。

本计划按普通电脑、单人制作、每天约60～90分钟安排。先用现有设备和工具，新增支出以按量调用为主；预算不含已有订阅费用、人工时间和推广费。

## 先固定第一条的制作规格

| 项目 | 试做标准 |
| --- | --- |
| 画面 | 9∶16竖屏，二维漫画；最终可导出1080×1920，源视频清晰度仍由生成规格决定 |
| 故事 | 1名主要角色、最多2个场景；一个冲突、一个反转 |
| 时长 | 45～60秒；旁白约180～250字，实际时长以试听为准 |
| 镜头 | 8～10个镜头；仅2个关键镜头用AI生成视频，其余用图片运镜 |
| 声音 | 先用一个系统旁白音色；音乐和音效只做必要点缀 |

## 第一阶段只使用三类工具

| 环节 | 工具 | 具体用途 |
| --- | --- | --- |
| 剧本与分镜 | 当前对话中的ChatGPT | 确定题材、旁白、镜头表、人物描述和提示词，沿用现有使用额度 |
| 图片与配音 | MiniMax开放平台 | image-01生成候选图；speech-2.8-turbo生成旁白，先按量试做 |
| 动态镜头 | MiniMax开放平台 | Hailuo-2.3-Fast图生视频，先测试768P、6秒 |
| 剪辑与导出 | 剪映桌面版 | 拼接图片和声音，添加关键帧推拉、字幕；先做10秒试导出确认所选功能费用 |

备用工具：即梦适合网页端试图和改图，具体额度与价格以登录界面为准；Shotcut为免费开源剪辑软件，可在剪映所需功能收费时替代。[3][4][5]

你有编程基础，后续接入API很合适。第一条只需要少量官方示例或本地调用脚本；做完3条之后，再把重复步骤串起来。

## MiniMax费用与样片预算

你提到的“minmax”应是MiniMax。开放平台提供按量API；海螺网页端则是创作产品。以下是中国站API价格，不能当成网页会员报价。注册后创建普通按量API Key，再按余额充值使用。[1][2]

| 能力与规格 | 官方单价 | 本计划的用法 |
| --- | --- | --- |
| image-01 / image-01-live | 0.025元／张 | 先低成本筛选角色与分镜；单价低不代表每张都能使用 |
| speech-2.8-turbo | 2.00元／万计费字符 | 初期旁白首选；使用系统音色 |
| speech-2.8-hd | 3.50元／万计费字符 | 需要时对同一段试听比较，再决定是否切换 |
| Hailuo-2.3-Fast 768P 6秒 | 1.35元／条 | 样片的主要动态镜头规格 |
| Hailuo-02 512P 6秒 | 0.60元／条 | 低清试动作可选；正式可用性需要自己检查 |
| MiniMax-H3 768P | 0.50元／输出秒 | 预算允许时再试；输入素材还可能单独计费 |

来源：[1]。Hailuo 2.3 Fast、02列在官方历史模型价格表，当前接口文档仍列有对应模型。[7] 正式使用前确认账户可用模型及报价。

语音计费特别注意：一个汉字计2个字符，标点、空格等另计。约250个汉字的旁白，生成三遍约1500计费字符，Turbo约0.30元，标点等会增加少量费用。[1]

| 一条约60秒的混合样片 | 算式 | 费用 |
| --- | --- | --- |
| 图片候选 | 40张 × 0.025元 | 1.00元 |
| 旁白重录 | 250汉字 × 2 × 3遍 ÷ 10000 × 2元 | 约0.30元 |
| 动态镜头重做 | 2个镜头 × 3个候选 × 1.35元 | 8.10元 |
| 模型调用合计 | 图片＋旁白＋视频 | 约9.40元 |

这是根据官方单价计算的示例，不是实测成片成本。两段选中的视频最多贡献12秒，其余时长由漫画图片运镜组成。若使用更高价格的模型、需要更多候选，或选用收费剪辑素材，费用会增加。

每条预留15～30元更稳妥。首周50元、首月200元是支出上限，不是平台最低充值额；只充值页面允许的最小合适金额，不预购大资源包。

作为对比：若60秒全部由10段6秒视频组成，每段都生成3个候选，仅视频约40.50元；剪掉不合格片段后还可能需要补镜头。控制动态镜头数量，比反复更换便宜平台更容易控制开支。

## 第一周完成首条样片

每次只学习当日用得到的功能。先让故事完整可看，再逐步改善画面。以下按7个工作步骤安排，时间不足时可以顺延。

| 步骤 | 要做的事 | 完成标志 |
| --- | --- | --- |
| 第1天 | 选一个熟悉的题材，找5条同类短片观察开头、节奏和镜头数量；写180～250字原创旁白 | 一个能在一分钟讲清的故事，开头3秒出现异常或冲突 |
| 第2天 | 注册MiniMax并确认充值规格；跑通一张图、一句配音；剪映用任意图片做10秒试导出 | 确认输入、下载、剪辑、导出整条流程可用 |
| 第3天 | 固定主角年龄、发型、服装、配饰和画风；选一张清晰参考图；做两个不同景别的验证图 | 三张图看起来是同一个人，再继续批量出图 |
| 第4天 | 拆8～10个分镜；先出低成本候选图，检查人物、构图和场景连续性 | 一组可按顺序看懂的分镜，关键动作已有合格首帧 |
| 第5天 | 生成旁白并试听，按实际语速调整镜头长度；先用图片剪出完整粗片 | 即使没有AI动态镜头，也能听懂并看懂故事 |
| 第6天 | 只给2个关键镜头生成短视频；加入必要音效和字幕，调整音量 | 45～60秒成片，字幕无错字、声音清晰 |
| 第7天 | 完整看两遍并用手机检查；选择一个平台发布或找3人试看；登记用时和花费 | 保存成片、剪辑工程、素材与第一条复盘 |

## 减少返工的四个做法

- 人物先定稿。每次都带同一参考图和固定描述；换服装、换脸或画风明显变化的候选图不进入视频阶段。MiniMax参考图接口当前一次支持一张主体参考图。[6]

- 先听旁白，再定镜头长度。需要缩短时先删句子，避免为凑时长重复生成视频。

- 每段动态镜头先做1个候选，检查后再决定要不要补。每镜头最多3次付费尝试；仍不好就简化动作或改用图片运镜。

- 所有候选都记录费用。接口生成成功但人物跑偏、动作不合适的素材，也要算入制作成本；不要把它当作免费失败任务。

首周的达标条件：有完整成片、角色基本稳定、声音能听清、故事能理解，并且总支出未超过50元。

## 后续三周形成可重复流程

| 阶段 | 制作安排 | 本周投入重点 |
| --- | --- | --- |
| 第2周 | 再做2条，累计3条；继续使用同一主角、画风和剪辑工程 | 比较不同开头；把素材命名、音量和字幕样式固定下来 |
| 第3周 | 再做2条，累计5条；复用已通过的角色和场景资产 | 只优化一个变量，例如冲突出现时间或旁白节奏 |
| 第4周 | 再做1条，累计6条；整理一次月度复盘 | 判断是否愿意继续、是否能稳定完成，以及哪类故事反馈更好 |

每周支出上限50元，30天总上限200元。达到预算上限就暂停付费生成，优先完成已有素材的剪辑。前一个作品尚未成片时，先完成它再增加题材。

## 每条视频只记录这些数据

| 记录项 | 用途 |
| --- | --- |
| 成片时长、制作小时数、实际支出 | 看一条作品是否能持续承担；记录所有候选和重做 |
| 图片与视频候选数、最终采用数 | 算采用率：采用数量÷候选数量；找到返工最多的环节 |
| 发布后固定时间的观看数据 | 例如发布后48小时记录播放量、平均观看时长、完播情况；以平台实际提供字段为准 |
| 观众原话与下条只改的一点 | 区分“没看懂”“节奏慢”“人物变脸”等具体问题 |

先比较自己相近时长的6条作品，不设“达到多少播放必赚钱”的标准。首月主要验证能否稳定制作和观众是否愿意看；收入暂不计入预算。

## 把编程能力用在最费时间的地方

第1～3条：手动选择剧本、人物和可用镜头，调用脚本只负责生成和下载。完成3条后，统计哪一步最耗时，再决定自动化范围。

- 优先自动化：分镜表导出、文件命名、批量配音、素材下载、费用汇总。

- 继续人工判断：剧情是否成立、人物是否一致、视频是否值得重做、最终节奏。

- 本地小工具即可先跑通；新增服务器、显卡和完整工作台的投入放到产出稳定以后评估。

## 今天的启动顺序

先确定一个短故事；再安装剪辑软件并完成10秒试导出；随后用MiniMax测试一张图和一句配音。当天能确认这三件事，就具备开始首条样片的条件。

## 首条样片选题示例

建议先试都市悬疑小故事《明天的系统日志》。程序员题材贴近你熟悉的工作，主角只需一个人，办公室和电脑屏幕可以反复使用。屏幕上的准确文字用剪辑字幕叠加，避免反复生图修字。

故事梗概：深夜值班的程序员收到明天的系统日志，日志准确预告了眼前的故障。最后一行提示有人将从身后进入，但他回头只看见自己。

| 时间 | 画面与剧情任务 | 制作方式 |
| --- | --- | --- |
| 0～4秒 | 屏幕出现未来日期，第一句就说明收到“明天的日志” | 屏幕图＋剪辑叠字＋提示音 |
| 4～10秒 | 主角看向时钟，确认时间不对 | 同一人物参考图＋缓慢推近 |
| 10～18秒 | 日志显示即将发生的故障 | 电脑局部图＋叠字 |
| 18～25秒 | 办公室灯光闪动，故障真的发生 | 第1个AI动态镜头，6秒片段配合定帧 |
| 25～34秒 | 主角翻到最后一行，发现是关于自己的记录 | 人物表情图＋屏幕特写 |
| 34～42秒 | 门外响起脚步，主角停下动作 | 门口图＋脚步音效 |
| 42～52秒 | 主角缓慢回头，身后出现相同身影 | 第2个AI动态镜头，剩余时长用反应图衔接 |
| 52～60秒 | 给出一次身份反转或新的具体线索，结束本集 | 定格画面＋简短旁白 |

这是试做结构，不是已完成脚本；镜头时长随实际旁白调整。旁白文本、人物设定和提示词确定后再付费生成。

## 本地笔记本与云端分工

不预先购置显卡、电脑或服务器。先使用现有笔记本完成一段10秒的浏览器操作与剪辑导出测试。

| 工作 | 实际计算位置 | 对本地电脑的影响 |
| --- | --- | --- |
| MiniMax API生成图片、配音、视频 | 服务商云端 | 本地负责提交请求、等待结果和下载素材，不需要在笔记本上运行生成模型 |
| 在线创作画布与云端工作流 | 云端模型计算，本地浏览器展示 | 同时打开太多素材、标签页或大型画布，仍会增加浏览器内存和显示负担 |
| 剪辑、预览、字幕和最终导出 | 本地剪辑软件 | 处理器、内存、显卡及硬盘会影响流畅度；先测试现有设备 |

低配置时的制作安排：

- 每集保持45～60秒，8～10个镜头，少量视频与图片混合，先用单条视频轨完成基本剪辑。
- 关闭多余浏览器标签页和其他软件，生成后分批下载、整理素材。
- 剪辑卡顿时先降低预览清晰度；软件支持代理素材时可启用，最终导出时再使用原始素材。
- 首轮测试可以先导出720p，确认流程和节奏后再做1080p版本。导出1080p不会把低清源素材变成真实高清细节。
- 如果本地仍无法完成短片，再比较网页云剪辑的费用、上传速度与导出限制，把支出计入原有200元预算。

设备是否够用以实际短片测试为准。升级前先记录具体瓶颈：浏览器卡顿、预览掉帧、内存不足，还是仅仅导出较慢。

## 在线画布工具补充

补充日期：2026年10月16日。

“在线画布”大致有两类：一种把角色图、分镜、提示词和视频放在同一个可视化空间，便于创作和修改；另一种把模型与处理节点连接起来，形成可重复执行的工作流。两者有些平台会同时提供。

| 工具 | 更适合做什么 | 在本计划中的用途 |
| --- | --- | --- |
| [即梦智能画布](https://jimeng.jianying.com/) | 多图层编辑、局部重绘、扩图、消除和抠图 | 第一周需要修人物或场景图时试用，尽量修改已有素材 |
| [RunningHub RHTV](https://rhtv.runninghub.cn/) | 用创作画布组织分镜、场景与素材，并生成AI视频；RunningHub也提供ComfyUI工作流 | 想在一个画布里观察整段故事时作为候选，先做小范围验证 |
| [TapNow](https://app.tapnow.ai/) | 把参考图、文字和视频节点连接，选择模型后生成，并进行裁剪、截帧等处理 | 适合试用“角色参考图 → 分镜 → 视频”的连续制作流程 |

选择建议：

- 第一条样片最多试一个画布工具。需要修改单张图时先看即梦；主要想把整组分镜连起来时，先比较RHTV与TapNow的界面和当前计费提示。
- 先完成一个人物参考图、两个分镜和一段短视频的小测试，确认下载和剪映导入可用，再扩大用量。
- 免费额度、会员价格和模型使用费以账号页面为准。使用画布不能直接套用MiniMax官方API单价；平台内模型费、算力费等按其收费说明记录。
- 同样的目标镜头，比较最终采用素材的成本与花费时间。画布主要节省组织和操作时间，不预设它一定比直接API便宜。
- 保留原来的首月200元总上限。画布测试费用从预算中支出，不另外增加预算。
