# Meme Scout 自我成长模式

[[Projects/Meme Scout|← Meme Scout 项目]]

## 模式目标

让每次改善留下可检查的假设、当时证据、新样本结果和结论变化。成长体现为判断更准确、数据更完整、研究更可复现；收益优势需要另行证明。

后台自动采集和计算分阶段结论。策略参数变更另立版本，保留旧协议；本模式不根据当天输赢自动优化参数，也不连接实盘。

## 固定循环

| 步骤 | 必须留下的内容 |
|---|---|
| 提出假设 | 具体问题、为什么值得验证、主指标与失败条件 |
| 固定方案 | 版本、入组、配对、费用、期限、缺失处理、容量限制 |
| 获取新证据 | 前瞻采样，包含未配对、未买入、缺失与失败 |
| 检查质量 | 时间、链和合约、报价、Gas、采样缺口、有效分母 |
| 比较结果 | 扣费收益、同组差、按链/币龄分层、最大赢家依赖、成本压力 |
| 更新认识 | 支持什么、不支持什么、仍不确定什么；对照上一次判断解释变化 |
| 下一轮 | 保留、停止、修复数据或建立一个新的信号假设；使用新版本与新样本 |

## 当前冻结假设

**H1**：当前V7.5技术信号的24小时扣费收益优于同类未入选币。

**H2**：已保存合格观察到确认入场之间的等待与价格上涨，可能影响入场质量。

H1有前瞻同类对照。H2目前是诊断性研究线索：小时观察不是精确首个信号，观察相关性不能证明“等待造成亏损”。不能据单个Temo案例优化一个买入阈值并宣布有效。

**H3**：GMGN标记钱包持续、分散的实际净买入所选候选，24h扣费收益优于同类普通候选。wallet-flow-study-v1网站能力已于10月19日第43版实施，第46版VPS安装及13:19重启后真实入库已核验；首次真实观察为10月19日12:51（北京时间）。第47版网站与更新包已补齐卖出转账拆分，用户已安装，09:27重启后新入库已确认。必须观察至少48h，覆盖达标才入组。H3不与H1合并样本。

H3对照不参考钱包状态，对照可能也有该信号；缺少完整证据时保留为未知。它不是钱包阳性/阴性的因果试验。只读接口的有限列表不能证明全链完整，标记钱包数也不等于净资金流入。新币迁移后的持续买盘继续留作后续假设，本轮不同时开启。

## 页面自动总结的阶段

1. 等待新样本。
2. 固定规则积累证据。
3. 样本够但覆盖不足：先修复数据。
4. 达到人工复核起点：检查绝对收益、相对对照、去掉最好一组和成本压力。
5. 初步有优势：下一批独立样本复验；或当前证据未达到升级条件。

复核起点为距首组至少7天、30个24小时完整配对、5个日期和80%到期配对完整率。它们不是盈利保证，也不是统计显著性门槛；H1每日2对的采样上限意味着30对至少约两周入组；H3每日1对、间隔24h，30对至少约一个月入组。

H3另有数据准入：48h观察、最近24h至少600轮、完整轮询率与时间覆盖均≥95%、最近30m至少12轮且全部完整、最新≤150秒。停机不算覆盖，异常卖出记录不被静默丢弃后拿来判定净买入。

## 每次分析的纪律

- 先查线上当前版本与采集时间，不把昨日快照称为今天实时数据。
- 按完整链与合约识别；同名DOPE不能跨链混为一个币。
- 区分账户累计、精确买入版本、独立入场研究、独立退出研究。
- 只有完整平仓才计整笔胜率，分批兑现不提前算赢。
- 收益与费用口径一致；已扣费收益不再减一次成本。
- 不用事后最高价改写过去决策，不把缺失当成零或成功。
- 保留有缺口和异常样本的数量，检查完整样本是否偏乐观。
- 对新证据修正认识，并写明分母变化；不为了维持旧判断而挑选结果。
- 每轮只推进有证据支持的改进，减少同时试很多规则再挑最好看的组合。
- 系统采集与公式计算不需要逐轮LLM长总结；只在用户要求、重要变化或阶段复核时输出简短结论。

## 本次自我复盘

之前修复覆盖、报价和执行模型改善了工程可靠性，但这些修复本身不证明选币有收益优势。后续报告必须把“系统正常工作”和“策略有盈利证据”分别说明。

一个具体例子：10月15日V4入场比较只有2个已完成配对时，连续确认组比直接组多亏约0.67美元；10月16日07:57有3个完整配对后，确认组因Solana DOPE未触发入场、避开其亏损，合计反而少亏约1.70美元。该变化来自新增配对分母，不代表确认规则突然被证明有效；实际已入场仍是0胜2负。Temo等待后买价更高的问题也仍值得独立检验。

今后使用“当前样本支持到什么程度”的表述，避免凭少数交易反复改变主策略。

## 交易冲突核查的纪律（10月19日追加）

读取权限通过与数据可用于模拟是两项检查。第45版允许partial数据启动只读观察、保存不一致变体，但该窗口不生成候选或新入组；不制造事件ID、不相加未核清金额。缺口在VPS本地持续标记30分钟，上传失败也不能跳过。48h累计小时不能替代覆盖准入。

当前已经确认GMGN返回数据，冲突原因仍未知；不能把“能安装”“接通API”写成“去重已完全修好”或“胜率已提高”。取得真实样本后再修改记录身份规则，旧样本保持原口径。

12:51钱包数据已真实入库。新取得的BSC回执证明，已报告案例是路由内两次真实成交，最终数量合计转入同一maker。第46版只对每笔日志唯一匹配、maker相符且代币数量守恒的情况合并，仍保留原分笔与日志索引；其他冲突继续未知。此前的“不能仅凭日志认定多笔”已由新回执证据具体化，不能把这一个案例推广为所有同hash差异都可相加。

## 卖出证据带来的修正（10月20日，第47版）

新增真实卖出回执表明，一个GMGN分笔可能对应多条直接转账，后面还会继续中转。此前逐条唯一匹配的规则过窄；第47版改为在有界、闭合路由中唯一分组，原子数量精确守恒，后续转发不重复加钱。不能由一个已核实买入案例宣布所有交易结构已修好。

GMGN原值的金额/数量与标价有0.0025%差异，具体来源未知。不能修改fixture让测试迎合旧假设，也不能无上限忽略差异；仅在完整卖出路由证明通过后允许最多0.01%，同时保存原值和差异，其余路径保留原检查。价格算术容差与策略交易阈值是不同口径，本次不修改后者或观察/覆盖门槛。

110项测试、类型和生产构建通过，网站第47版已发布并验明线上包；用户已完成VPS安装，网站09:27:42确认新数据。本批无待合并动作，合并计数0不能当作失败；No entries也须结合随后新入库判断。原首次观察时间保留，既有缺口不补齐，钱包0配对。此次结论是已验证受测卖出核算边界，收益优势继续未知。

## 质量诊断带来的修正（10月21日，第48版）

1. 先拆分状态来源再决定修什么。08:23快照的275轮不完整中180轮仅在等待，不能写成275次漏采；轮询间断、当前异常、故障后等待分别报告。
2. 活跃窗口的判断要先排除所有变体均已过期的冲突，再合并检查身份；已有等待截止仍保留。任何一个时间变体可能当前时继续拦截，不用过期规则掩盖真正歧义。
3. 同交易、同maker字段不保证所有转账属于同一钱包。真实批量交易有不同最终接收者，不可为达到覆盖率而相加、扩大证明上限或回填历史完整。
4. 本轮116项测试及页面检查证明受测工程行为；48h/95%质量和主交易参数均未改。网站发布、VPS安装、新数据验收、前瞻收益分别记录。第48版仍待VPS运行更新命令，收益优势未知。

## 重新梳理策略（10月22日）

本轮把工作重心从持续工程升级转回收益归因。固定09:00快照，24个V7.5仓位逐笔核对，20笔平仓4胜16负、净亏$29.0093，4个持仓不计入胜率。16笔亏损中14笔持有期采样最大涨幅不足10%；14笔初始止损均在首个已采样越线报价后约7.9～23.6秒退出。价格变化约亏$21.7053，执行摩擦约$7.3040，费用不是全部原因。已到卖出后24h的14笔亏损中10笔价格继续下跌，保留止损有依据。

更新认识：当前优先检验筛选与入场质量，不能先认定卖晚了、Gas太贵或再升级一次即可改善。高分描述交易特征，不能当盈利概率；单个反弹、单笔追高和7笔Solana全亏都不能直接变成新门槛。持仓路径只是离散采样，不代表抓得到最高价。

已完成买入事件、卖出份额、累计收益、费用和价格贡献的独立账本核对，保留完整链/合约身份与24笔CSV。AZTEC开仓超过导出7日边界，其后未知不写成实际停采。H1仍只有5个完整24h配对且平均差为负，钱包H3覆盖不足且0配对。现有V7.5保留为未通过盈利验证的固定基准，本轮没有修改运行中的买卖参数，也没有发布采集器新版。
