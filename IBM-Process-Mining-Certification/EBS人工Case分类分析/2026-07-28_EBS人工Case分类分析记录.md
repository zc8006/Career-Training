# EBS人工 Case 分类分析记录

更新时间：2026-07-28

## 当前分析目标

只分析同时满足以下条件的 Case：

- `System <> 'DDD'`
- `OCRFeedback = 'EBS'`
- Event 中存在 `审批结束`
- Event 中不存在 ChinaBot/ChinaBOT 执行的 `录入完成`
- Tracker 中也未被判定为 RPA
- 存在审批以外的人工 Activity

当前已经取得三个分析字段：

- `UUID`
- `EVENT_COMMENT_TIMELINE`
- `TRACKER_INFO`

其中：

- `EVENT_COMMENT_TIMELINE`：按时间合并 Event 与 Comment，例如：
  `合同FSD20250208ENG(CNVITA05) -> 录入完成(CNVISP97) -> 审批结束(CNVITA05)`
- `TRACKER_INFO`：拼接 Tracker 中的 System、OCRFeedback、POResult、POCompareResult、PrepaymentResult、ESignResult、ContractOrPO、Comment_Clean 等字段。

## IPM SQL限制

当前环境中一使用 `WITH`（CTE）就报错，因此后续SQL统一遵循：

- 不使用 `WITH`
- 改用多层子查询
- 多分类使用 `UNION ALL`
- 最外层再进行 `GROUP BY` 和 `COUNT(DISTINCT UUID)`

## 分类原则

### 1. 意见征询单独处理

只要 Case 中出现 `意见征询`，第一张大分类图中只归为：

- 意见征询

不再同时归入更系统、更PO、补发票等其他类别。

后续再单独建立“意见征询专项分类”，分析意见征询之后的处理动作。

### 2. 非意见征询 Case 允许多分类

一条 Case 中可能同时存在多个原因，例如：

- 合同/材料
- 发票相关
- 更系统

因此不能使用只能返回单一结果的 `CASE WHEN`，而应使用 `UNION ALL`，让一个 UUID 可以命中多个分类。

每个分类内部使用：

```sql
COUNT(DISTINCT UUID)
```

避免同一个 Case 因同类关键词重复出现而重复计数。
