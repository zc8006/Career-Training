# Day60 自我成长记录

## 今天最大的变化

Day60 的重点不是又学了多少 JVM 名词，而是开始出现“旧弱点真正变稳”的迹象。

### 1. JVM 五大区域：从长期漏项到首次完整输出

之前多轮只能稳定说出“堆、栈、程序计数器”，本地方法栈和方法区反复遗忘。Day60 已能无提示、术语标准地完整说出：

> 堆、虚拟机栈、程序计数器、本地方法栈、方法区。

当前判断：开始稳定，但仍需按间隔复习机制继续延迟抽查，不能因为一次 10 分就直接判定长期掌握。

### 2. GC Roots：从顽固弱项进入较稳定阶段

Day56/57 还几乎完全记不住，随后逐步形成“栈、静态、常量、Native”这条记忆链。Day59、Day60 连续无提示完整输出。

当前判断：较稳定，下一步减少高频重复，改成 D+3 / D+7 延迟复测。

### 3. 四种引用：概念边界已经基本形成

早期强引用、虚引用经常说反，Day60 已能完整说出：

- 强：强引用可达时正常 GC 不回收
- 软：内存紧张时可能回收
- 弱：只剩弱引用时 GC 可以回收
- 虚：主要跟踪回收状态

当前判断：从“知道但说不全”进入“能够完整输出”。

### 4. 对象生命周期主线越来越完整

目前已经能理解并连接：

`new 对象 → Eden → Minor GC → Survivor → 多次存活/年龄增加 → 晋升老年代`

并开始进一步理解：

- Survivor 为什么要两个：配合复制算法
- 老年代为什么不适合一直复制：存活对象多，复制成本高
- 对象晋升：年龄达到阈值、Survivor 空间压力等都可能影响晋升

这说明 JVM 学习正在从孤立八股向“对象生命周期 + GC 机制”模型发展。

## 今天暴露出的新问题

### 1. 年轻代结构仍是顽固弱点

Day60 在“年轻代有哪些区域”这一题上把答案说成 Minor GC，说明：

> 回收动作和内存区域这两个概念仍可能混淆。

需要固定：

> 年轻代是 Eden + S0 + S1；Minor GC 是对年轻代进行的一类回收。

这题重置为 D+1。

### 2. STW 仍容易被绑定成 Full GC

已经知道 Full GC 会带来明显停顿，但容易形成错误等式：

> STW = Full GC

需要继续强化：

> STW 是 JVM 在某些 GC 阶段暂停用户线程的现象，不只 Full GC。

### 3. 内存泄漏已经理解本质，但典型场景储备不足

Day60 能说出“对象一直被引用，GC 回收不了”，说明本质已经懂；但场景输出仍弱。

下次至少应能主动说出 3 个：

- static List/Map 长期持有对象
- 缓存无淘汰策略
- ThreadLocal 在线程池里使用后不 remove

监听器未注销可作为补充。

## Day60 新增的进阶能力

今天接触了 TLAB、逃逸分析、标量替换。

这三题不是当前阶段必须和 HashMap、Spring 事务一样背到 10 分的高频题，而是 JVM 追问时的加分项。

当前目标只要求“一句话能说清”：

> TLAB：Eden 中给线程预留的小块分配空间，减少对象分配竞争。

> 逃逸分析：判断对象是否逃出当前方法或线程。

> 标量替换：把未逃逸对象拆成若干基本变量，减少真实对象分配和 GC 压力。

后续不要为了“学 JVM”不断往低收益源码细节钻，优先保证高频题稳定。
