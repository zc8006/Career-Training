# Day59 自我成长记录

## 今日定位

Day59 的重点不是继续堆 JVM 新概念，而是验证 Day57～Day58 学到的内容能否在间隔后无提示输出，并把 JVM 学习从“记名词”推进到“理解 GC 对应用的影响”。

## 一、今天最明显的成长

### 1. GC Roots 从顽固弱项进入初步稳定

之前经历：

- Day56：不知道
- Day57：没记住
- Day58：能说“栈、静态、常量”，漏 Native
- Day59：能完整说出“栈、静态、常量、JNI / Native”

这说明间隔回炉开始形成长期记忆，不再只是当天听懂。

当前评级：**理解层 2 / 4，初步稳定**。

下一步：不仅要会列 Roots，还要能解释“为什么 GC 要从 Roots 出发做可达性分析”。

### 2. 四种引用从混淆进入可输出阶段

Day58 还会把强引用和虚引用说偏，Day59 已经能基本完整说出：

- 强引用：可达时正常 GC 不回收
- 软引用：内存紧张时可能回收
- 弱引用：只剩弱引用时 GC 可回收
- 虚引用：跟踪对象回收

当前评级：**知道 → 理解过渡，2 / 4**。

下一步：后续结合缓存、ThreadLocal、ReferenceQueue 逐步进入应用层。

### 3. JVM 五大区域终于从“3 个”突破到“5 个”

长期问题是只稳定记住：堆、栈、程序计数器。

Day59 已经能把另外两个也想出来，只是名称说成了“本地内存方法、内存方法”。说明记忆内容已经建立，当前主要是术语精确度问题。

需要固定：

> 本地方法栈、方法区。

当前评级：**知道层接近稳定，1.5 / 4**。

### 4. JVM 对象生命周期主线开始真正连起来

当前已经能持续理解：

`new 对象 → Eden → Minor GC → Survivor → 多次存活 → 晋升老年代`

而且不只是记流程，已经能解释一部分设计原因：

- Survivor 两个区是为了配合复制算法
- 年轻代对象存活少，复制成本低
- 老年代存活对象多，不适合一直复制
- Full GC 范围更大，因此通常比 Minor GC 更慢

这是今天最重要的成长：**知识点开始形成因果链，而不是孤立八股。**

当前评级：**理解层 2 / 4**。

## 二、今天暴露出的新短板

### 1. GC 算法仍然是“知道但输出不完整”

今天回答“复制法、标记删除整理”，说明：

- 复制算法已经进入记忆
- 标记-清除和标记-整理仍会混合
- 分代收集容易漏

继续固定保命句：

> 标记清除、复制、标记整理、分代收集。

这题继续按弱项处理。

### 2. “会列场景”不等于“答到问题核心”

事务题问的是：

> 为什么同类内部调用会让 @Transactional 失效？

回答却列出了 private、catch、new Bean、异常类型等全部事务失效场景。

这说明知识本身是会的，但面试表达出现了新的瓶颈：**没有先判断题目到底在问“是什么、为什么、怎么办”中的哪一类。**

后续训练增加一个输出要求：

> 先用一句话正面回答问题，再补充扩展。

目标从“背得多”提升到“回答精准”。

### 3. 内存泄漏与 OOM 尚未建立边界

今天把“内存泄漏”直接等同于“内存溢出”。

必须固定因果：

> 内存泄漏 = 对象没用了，但引用还在，GC 回收不了。
>
> OOM = 内存不足，无法继续分配。
>
> 泄漏长期累积可能导致 OOM。

这是 Day60 的高优先级回炉题。

### 4. STW 是全新概念

当前只建立了：

> STW = GC 某些阶段暂停用户线程。

下一步要把它和实际性能问题连接起来：

> STW 时间长 → 接口延迟升高 / 服务卡顿 → 需要结合 GC 日志排查。
