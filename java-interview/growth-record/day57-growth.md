# Day57 自我成长记录

## 今日主题
JVM GC 间隔回炉 + Spring / 并发稳定性复测

## 一、今日成长结论

Day57 的价值不在于“又学了多少新题”，而在于验证哪些知识已经真正留下来，哪些仍然只是短期记忆。

今天出现了一个很清晰的分层：

- Spring 事务失效：已经可以多轮无提示完整回答，进入较稳定阶段。
- Spring 三级缓存：之前长期把二级缓存说成“声明好的 Bean”，今天终于稳定说出“提前暴露的 Bean 引用”。
- ConcurrentHashMap：JDK7 / JDK8 的边界已经基本固定。
- JVM 基础：堆、栈、程序计数器能主动想起，但本地方法栈、方法区仍会遗忘。
- JVM GC：GC Roots、四种引用、GC 算法仍然明显不稳，需要继续高频间隔回炉。

## 二、从 Day56 到 Day57 的具体进步

### 1. StackOverflowError
Day56 还曾把它和“大数据量进入堆”混在一起。

Day57 已经能主动回答：

> 方法调用太深，尤其是递归容易导致 StackOverflowError。

这说明已经从“概念混淆”进入“能够区分”。

### 2. @ConditionalOnClass
之前容易理解成“按照配置加载”。

Day57 已经能够说出：

> 有指定类存在时配置才生效。

这是一个典型的顽固错题转正过程。

### 3. ConcurrentHashMap
之前 JDK8 曾错误带上 Segment，之后又把 synchronized 说成“异步锁”。

Day57 已经能回答：

> JDK7 分段锁；JDK8 CAS + synchronized。

说明版本边界开始进入稳定记忆。

### 4. Spring 三级缓存
这是今天最明显的术语进步之一。

之前反复说：

> 二级缓存是“声明好的 Bean”。

Day57 已经主动改成：

> 二级缓存放提前暴露的 Bean 引用。

这说明不只是“知道意思”，而是面试输出术语也在逐渐固定。

## 三、仍需警惕的假性掌握

### GC Roots

当前不能标记为掌握。

### 四种引用
只能记住强引用、弱引用的大方向，软引用和虚引用仍不稳。

当前处于“知道但不能完整输出”。

### GC 算法
Day57 只能主动想起“复制算法”。

标记清除、标记整理、分代收集仍需强化。

## 四、今天新建立的 JVM 主线

今天开始不再把 JVM 只当作零散知识点，而是建立对象生命周期链路：

> 新对象 → Eden → Minor GC → Survivor → 多次存活 → 晋升老年代

围绕这条线，今天新增：

- Minor GC / Major GC / Full GC
- 年轻代为什么适合复制算法
- Eden + S0 + S1
- 对象什么时候进入老年代

目前只有“年轻代对象死得快、活得少，所以适合复制算法”能部分主动回忆，其余仍属于刚建立认知。
