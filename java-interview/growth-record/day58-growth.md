# Day58 自我成长记录

## 今日结论

Day58 的重点变化不是“又背了多少 JVM 名词”，而是开始把 JVM GC 从零散记忆串成对象生命周期主线：

`new 对象 → Eden → Minor GC → Survivor → 多次存活 → 晋升老年代`

这条线一旦稳定，后续 GC 算法、分代思想、对象晋升和 Full GC 都更容易理解，而不只是死记。

## 四、今天最重要的成长：开始从背题转向原理链路

今天出现了几个值得保留的推理：

1. 大多数对象生命周期短 → 新对象先进入 Eden
2. 年轻代存活对象少 → 复制算法成本低
3. 复制算法需要 From / To → Survivor 设计成两个
4. 对象多次存活 → 年龄增加 → 晋升老年代
5. 老年代存活对象多 → 复制大量对象成本高 → 不适合一直用复制算法

这已经开始形成“为什么这样设计”的回答能力。
