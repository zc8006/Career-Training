## 一、旧题回炉

### 1. 年轻代一般分成哪些区域？

用户回答：`Eden，S`

评分：6/10

标准答案：

> 年轻代通常分为 Eden、Survivor 0、Survivor 1，也就是 Eden + S0 + S1。

保命句：

> 年轻代 = Eden + S0 + S1。

状态：有记忆残留，但结构仍不稳定。

---

### 2. Survivor 区主要是干什么的？

用户回答：`主要是为了复制算法`

评分：7/10

纠正：

> Survivor 主要存放 Minor GC 后仍然存活的对象，并配合年轻代复制算法使用。

保命句：

> Survivor 放 GC 后还活着的对象，并配合 S0、S1 做复制。

---

### 3. 为什么 Survivor 要设计成两个，而不是一个？

用户回答：`为了配合年轻代的复制算法`

评分：8/10

补充：

> 两个 Survivor 可以轮流作为 From 区和 To 区，把存活对象复制到另一个空区，再整体清空原区域。

保命句：

> 两个 Survivor 轮流复制，方便清理存活对象，也减少内存碎片。

---

### 4. 对象什么时候从年轻代晋升到老年代？

用户回答：`经历过多次回收后，到达一定的年龄就晋升了`

评分：10/10

标准答案：

> 对象经历多次 Minor GC 后仍然存活，年龄达到晋升阈值，就可能进入老年代；大对象或 Survivor 空间不足时也可能提前晋升。

保命句：

> 对象活得够久，年龄到了，就晋升老年代。

状态：已连续多轮答对，进入较稳定阶段。

### 6. 强引用、软引用、弱引用、虚引用分别有什么特点？

用户回答：`强引用是不会被GC回收，软引用在空间不足的时候可能回收，弱引用是下次回收的对象，虚引用是跟踪回收情况`

评分：9.5/10

标准答案：

> 强引用可达时正常 GC 不会回收；软引用在内存紧张时可能回收；只剩弱引用时对象在 GC 时可能被回收；虚引用不影响对象生命周期，主要配合 ReferenceQueue 跟踪对象回收。

保命句：

> 强不收，软紧张收，弱 GC 收，虚跟踪回收。

状态：从混淆进入基本稳定。

### 8. Minor GC 和 Full GC 有什么区别？

用户回答：`Minor GC是针对年轻代的回收，full GC是整体的回收`

评分：9/10

标准答案：

> Minor GC 主要针对年轻代；Full GC 回收范围更大，通常会涉及整个堆，停顿也通常更明显。

保命句：

> Minor GC 回年轻代，Full GC 回收范围更大。

保命句：

### 10. 同一个类内部方法调用为什么会导致 @Transactional 失效？

用户回答：`内部调用，private，被catch住，自己创建bean，异常类型不对`

评分：7/10

问题：答成了“事务失效场景汇总”，没有直接回答原因。

标准答案：

> Spring 事务基于 AOP 代理实现。同类内部调用本质是 this.xxx()，没有经过 Spring 代理对象，因此事务增强不会生效。

保命句：

> 内部调用走 this，没有经过代理对象，所以事务失效。

成长点：开始需要从“会背场景”提升到“问什么答什么、解释机制”。

## 二、Day59 新题

### 1. 什么是 Stop-The-World？

用户回答：`不知道`

评分：0/10

建立概念：

> Stop-The-World（STW）是 JVM 在某些 GC 阶段暂停用户线程，只让 GC 相关线程工作的现象。

保命句：

> STW 就是 GC 时暂停用户线程。

---

### 2. 为什么 Full GC 通常比 Minor GC 更慢？

用户回答：`full GC是整体的一次，范围广`

评分：8/10

标准答案：

> Minor GC 主要处理年轻代，范围较小、存活对象通常较少；Full GC 涉及更大内存范围，需要扫描和处理更多对象，因此通常更慢，STW 停顿也可能更明显。

保命句：

> Minor GC 范围小，Full GC 范围大、处理对象多，所以通常更慢。

---

### 3. 什么叫内存泄漏？

用户回答：`内存泄漏就是内存溢出`

评分：2/10

纠正：

> 内存泄漏：对象已经不再需要，但仍被引用，GC 无法回收。
> 内存溢出 OOM：JVM 已经没有足够内存继续分配新对象。

二者关系：

> 内存泄漏严重时，可能最终导致 OOM。

保命句：

> 内存泄漏是该回收的对象没被回收；内存溢出是内存真的不够用了。

---

### 4. Java 常见内存泄漏场景有哪些？

用户回答：`不知道`

评分：0/10

常见场景：

- static Map / List 长期持有对象，只加不删
- 缓存没有淘汰策略
- 监听器、回调注册后没有注销
- ThreadLocal 在线程池中使用后没有 remove
- 数据库连接、流等资源长期不释放（属于资源泄漏，和堆内存泄漏概念需区分）

保命句：

> 内存泄漏本质就是：对象没用了，但引用还在，GC 回收不了。
