## 一、今日回顾

### 1. StackOverflowError
**回答：** 方法太深了，一般递归会引起这种问题。

**评分：9/10**

**标准表达：** 方法调用层级过深，栈帧不断增加，最终耗尽线程栈空间，常见于无限递归或递归层级过深。

**保命句：** 递归太深，栈帧不断增加，最后 StackOverflowError。

**成长判断：** Day56 还与“大数据量进堆”混淆，Day57 已能主动区分，进入短期稳定。

### 3. 堆和栈的区别
**回答：** 堆主要存放对象，栈是存放方法的信息。

**评分：8/10**

**补充：** 堆主要存对象实例和数组，是线程共享区域，也是 GC 的主要区域；栈存方法调用产生的栈帧、局部变量等，是线程私有的。

**保命句：** 对象主要在堆，方法执行信息主要在栈；堆共享，栈私有。

**成长判断：** 从 Day55 的薄弱状态，已提升到能稳定说出核心区别。

---

### 4. @ConditionalOnClass / @ConditionalOnMissingBean
**回答：** ConditionalOnClass 是有类存在就进行配置；OnMissingBean 是用户没有创建 Bean 时自动创建 Bean。

**评分：9/10**

**标准答案：**
- `@ConditionalOnClass`：类路径中存在指定类时，配置才生效。
- `@ConditionalOnMissingBean`：容器中不存在指定 Bean 时，才创建默认 Bean。

**保命句：** OnClass：有这个类才配；OnMissingBean：没这个 Bean 才建。

**成长判断：** 从 Day55 0 分、Day56 半对，进步到 Day57 基本完整，开始趋稳。

---

### 5. ConcurrentHashMap JDK7 / JDK8
**回答：** JDK7 使用分段锁，JDK8 使用 CAS + synchronized。

**评分：9/10**

**标准答案：**
- JDK7：Segment + ReentrantLock
- JDK8：取消 Segment，使用 CAS + synchronized

**保命句：** JDK7：Segment + ReentrantLock；JDK8：CAS + synchronized。

**成长判断：** JDK7 / JDK8 边界已经明显稳定，术语也基本正确。

---

### 6. Spring 三级缓存
**回答：** 一级缓存放初始化完整的 Bean，二级缓存放提前暴露的 Bean 引用，三级缓存放 ObjectFactory，三级缓存是为了解决互相依赖的问题。

**评分：9.5/10**

**标准答案：**
- 一级缓存 `singletonObjects`：完整初始化后的单例 Bean
- 二级缓存 `earlySingletonObjects`：提前暴露的 Bean 早期引用
- 三级缓存 `singletonFactories`：`ObjectFactory<?>`

主要用于解决部分单例 Bean 的循环依赖问题，并能配合 AOP 获取早期代理引用。

**保命句：** 一级完整 Bean，二级早期引用，三级 ObjectFactory；三级缓存解决部分单例循环依赖。

**成长判断：** 之前反复说“声明好的 Bean”，Day57 已稳定改成“早期引用”，这是明显进步。

---

### 7. Spring 事务失效场景
**回答：** private、内部方法调用、自己创建的 Bean、异常类型不对、异常被 catch 住。

**评分：10/10**

**标准答案：** private 方法、同类内部 `this.xxx()` 调用、对象不是 Spring 容器管理而是自己 new、异常类型不满足回滚规则、异常被 catch 后未继续抛出等。

**保命句：** 事务失效本质看两件事：有没有经过代理，异常有没有正确抛出来。

**成长判断：** 已经过多轮抽查，属于当前长期较稳定知识点。

## 三、Day57 新题

### 1. Minor GC / Major GC / Full GC
**首次回答：** 不知道。

**评分：0/10**

**新建认知：**
- Minor GC：主要回收年轻代
- Major GC：通常理解为老年代 GC，但术语在不同收集器中定义不完全一致
- Full GC：范围更大，通常涉及整个堆，并常伴随方法区 / 元空间等区域的回收检查

**保命句：** Minor GC 看年轻代，Full GC 范围最大；Major GC 通常理解为老年代回收。

---

### 2. 年轻代为什么适合复制算法
**回答：** 因为年轻代更新比较快。

**评分：7/10**

**标准表达：** 年轻代对象大多数生命周期很短，每次 GC 后存活对象较少，因此只复制少量存活对象效率较高，而且还能避免内存碎片。

**保命句：** 年轻代对象死得快、活得少，所以适合复制算法。

**成长判断：** 有旧知识残留，能主动想起核心方向，理解已开始形成。

---

### 3. 年轻代区域划分
**首次回答：** 不知道。

**评分：0/10**

**新建认知：** 年轻代通常分为 `Eden + S0 + S1`。

**保命句：** 年轻代 = Eden + 两个 Survivor。

---

### 4. 对象何时晋升老年代
**首次回答：** 不知道。

**评分：0/10**

**新建认知：** 对象在年轻代经历多次 Minor GC 后仍然存活，年龄达到晋升阈值时可能进入老年代；大对象或 Survivor 空间不足时也可能提前晋升，具体规则依赖垃圾收集器和 JVM 配置。

**保命句：** 对象在年轻代活得够久，就会晋升老年代。
