### 2. 强引用、软引用、弱引用、虚引用分别有什么特点？

用户回答：强引用是不是能回收；软引用容量紧张时回收；弱引用一般下次可回收；虚引用用来判断哪些可以引用。

评分：6/10。

纠正：
- 强引用：只要对象仍被强引用且可达，正常 GC 不会回收
- 软引用：内存紧张时可能被回收
- 弱引用：如果只剩弱引用，发生 GC 时可以被回收
- 虚引用：不决定对象生命周期，常配合 ReferenceQueue 跟踪回收状态

保命句：强引用不回收，软引用内存紧张时回收，弱引用 GC 时可回收，虚引用主要用于跟踪回收。

### 6. Minor GC 和 Full GC 有什么区别？

用户回答：Minor GC 用于年轻代回收；Full GC 是老年代对象满了启动一次。

评分：7/10。

纠正：Minor GC 主要回收年轻代；Full GC 范围更大，通常涉及整个堆。老年代空间不足只是可能触发 Full GC 的原因之一。

保命句：Minor GC 看年轻代，Full GC 看整体。

### 8. 对象什么时候从年轻代晋升到老年代？

用户回答：经历多次回收后，时间够久就会晋升。

评分：9/10。

## 新题

### 1. 为什么 Survivor 区要设计成两个，而不是一个？

起初用户不知道 Survivor 区是什么。

重新建立：Survivor 是年轻代中用于保存 Minor GC 后仍存活对象的区域，年轻代通常为 Eden + S0 + S1。

用户进一步回答：那就是年轻代复制回收的方法。

评分：8/10。

纠正：两个 Survivor 区是为了配合复制算法，S0/S1 在不同 GC 周期中轮流作为 From / To 区，存活对象来回复制，可减少碎片并方便整体清理。

### 2. 一个对象刚 new 出来一般最先分配到哪里？

用户回答：栈区吗？

评分：3/10。

纠正：对象实例通常在堆中，新对象一般优先进入年轻代 Eden；局部变量中的对象引用可位于栈帧局部变量表。

保命句：引用可以在栈，对象通常在堆；新对象一般先到 Eden。

### 3. 为什么大多数新对象先放 Eden，而不是直接进老年代？

用户回答：回收更快吗？

评分：7/10。

纠正：核心是分代假说——大多数对象生命周期很短。把新对象放 Eden，可以通过范围较小、频率较高的 Minor GC 快速回收大量短命对象，提高效率。

### 4. 为什么老年代不能也一直用复制算法？

用户回答：老年代更新慢，复制法占用空间比较大。

评分：9/10。

纠正：老年代对象存活率高，如果使用复制算法，需要复制大量存活对象，时间成本和额外空间成本都高，因此更适合标记-清除或标记-整理等思路。

保命句：年轻代活得少，适合复制；老年代活得多，复制成本太高。

## Day58 面试主线

`new 对象 → Eden → Minor GC → Survivor → 多次存活 → 晋升老年代`

进一步理解：

- 大多数对象朝生夕死，所以先放 Eden
- 年轻代存活对象少，所以适合复制算法
- S0 / S1 是复制算法的配套结构
- 老年代存活对象多，所以不适合持续使用复制算法
