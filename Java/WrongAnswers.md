### int 和 Integer 的默认值

我的回答：

```text
int 的默认值是 0，Integer 的默认值是 null。
```

问题点：

这句话缺少适用范围。只有成员变量和数组元素由 JVM 提供默认值；局部变量没有默认值，使用前必须显式赋值。

背诵版：

```text
int 是基本类型，Integer 是包装类。成员变量和数组元素的默认值分别是 0 和 null；
局部变量没有默认值，使用前必须赋值。Integer 为 null 时自动拆箱会发生空指针异常。
```

是否已掌握：Almost

### Spring Boot 自动配置的完整链路

我的回答：

```text
引入 Starter 后把依赖放到 classpath，EnableAutoConfiguration 根据条件创建 Bean，
自己定义了就不会自动创建。
```

问题点：

核心方向正确，但多次回答后才补齐“加载候选配置类”和常见条件注解，口述稳定性不足。

背诵版：

```text
Starter 引入相关依赖；@EnableAutoConfiguration 加载候选自动配置类；
再由 @ConditionalOnClass、@ConditionalOnProperty、@ConditionalOnMissingBean 等条件判断；
条件满足时创建默认 Bean，用户已经自定义相应 Bean 时自动配置通常会退让。
```

是否已掌握：Almost

### 缓存穿透、击穿和雪崩

我的回答：

```text
最初把缓存雪崩理解成服务 A 调用服务 B，B 宕机后请求一直等待。
```

问题点：

这是微服务中的级联故障或服务雪崩，不是 Redis 缓存雪崩。三者定义已经能够区分，但解决方案还不够稳定。

背诵版：

```text
穿透是查询数据库也不存在的数据，可用参数校验、缓存空值和布隆过滤器；
击穿是单个热点 Key 失效，可用互斥锁或逻辑过期；
雪崩是大量 Key 同时失效或 Redis 故障，可用随机 TTL、限流降级、多级缓存和 Redis 高可用。
```

是否已掌握：Almost

### 布隆过滤器在实际开发中的使用

我的回答：

```text
不知道布隆过滤器是什么，也不知道数据怎么添加。
```

问题点：

需要掌握初始化、查询、增量同步和误判四个环节，不能只背“用于防缓存穿透”。

背诵版：

```text
启动或定时重建时把数据库已有 ID 加入布隆过滤器；新增数据在数据库提交成功后增量加入。
查询结果为不存在时可以直接拒绝；结果为存在时仍要查询缓存或数据库，因为布隆过滤器存在误判。
标准布隆过滤器不适合直接删除，数据偏差较多时可以重建并切换。
```

是否已掌握：Almost

### Redis 分布式锁的可靠实现

我的回答：

```text
服务器加锁后宕机会造成死锁，所以要设置过期时间；
唯一值防止误删别人的锁；解锁使用 Lua 保证判断和删除的原子性。
```

问题点：

主要风险已经掌握；需要继续保持“加锁与 TTL 也必须原子完成”这一点，并准备锁续期、业务超时和主从切换追问。

背诵版：

```text
使用 SET key uniqueValue NX EX ttl 原子加锁；TTL 防止永久死锁；
uniqueValue 标识锁持有者；解锁使用 Lua 原子比较并删除。
Java 项目通常优先使用 Redisson，并了解看门狗续期机制。
```

是否已掌握：Almost

## 示例

### RowBounds 是什么？

我的回答：

```text
RowBounds 是逻辑分页，有可能拆分的不对。
```

问题点：

```text
表达不准确，“拆分的不对”不适合面试。
```

背诵版：

```text
RowBounds 偏逻辑分页，可能先查出大量数据再在内存中截取，所以大数据量分页不推荐。
项目中一般使用 PageHelper 或手写 limit。
```

是否已掌握：Almost
