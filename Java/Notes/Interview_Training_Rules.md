# Java 面试训练规则

## 当前进度

- 最新进度：Day 27
- 训练目标：高频 Java 后端面试题能稳定说出来，而不是只看资料

## 固定训练节奏

每天按这个顺序来：

1. 旧题回炉 8～10 道
2. 新题 4～6 道
3. 追问 3～5 个以内
4. 最后给 8～10 句背诵清单

不要无限加题。每个阶段完成后要明确提示。
如果需要加练，再单独进入加练。

## 训练方式

流程固定：

```text
我先答 → 打分 → 答错或不完整就给保命答案 → 我重新答一遍 → 后续回炉
```

重点不是答案写得多，而是：

- 能说出口
- 能记住
- 能接追问
- 能结合项目场景

## 复习比例

每天按：

```text
60% 复习旧题
40% 学新题
```

正常一天控制在：

```text
主问题 12～16 道
追问 3～5 个
背诵句 8～10 句
```

状态好最多 18 道；状态差只做 8～10 道回炉，不加新题。

## 题目状态

每道题分 3 类：

### A：稳定掌握

能不看答案完整说出来，追问也能接住。

### B：半熟

知道关键词，但说不完整，需要继续回炉。

### C：不会或容易混

第一次接触，或者答错，进入错题本。

## 防遗忘机制

一题至少过三关：

1. 当天能说
2. 第二天闭卷能说
3. 第 4 天、第 7 天还能说

真正掌握的标准不是“今天听懂了”，而是隔几天还能稳定说出保命答案。

## 错题本格式

```text
题目：
我的原回答：
问题点：
正确关键词：
保命答案：
下次复查时间：
状态：No / Almost / Yes
```

## 面试表达原则

每个高频题都尽量按三层回答：

```text
概念：这个技术是什么
项目：我项目里怎么用
排查：出问题怎么定位
```

示例：

```text
MyBatis 是持久层框架，用来简化 JDBC。
在 Spring Boot 项目里，一般由 Controller 接收请求，Service 处理业务，Mapper 调用 MyBatis 执行 SQL。
如果 SQL 慢，我会先看日志确认 SQL，再看 EXPLAIN，检查索引是否命中，必要时优化 SQL、分页或加索引。
```
